## 1. 总体设计

### 1.1 三层结构

```
主线（唯一新手引导）
└── 阶段 Stage（29 个，见 §3）
    ├── 一个 MissionV2 主线任务（Category.MAIN，任务列表一行）
    ├── 一个 NPC（dialogId）+ 一棵对话树
    ├── 一个世界目标（kill / reach / level / instance / daily / talk）
    └── 一次「交付对话」——阶段推进只在这里发生
```

### 1.2 阶段状态机（核心）

任务侧沿用 `MissionV2.Status`；阶段侧在其上增加「是否解锁」：

| 状态 | 存储 | 含义 | 任务列表 |
|---|---|---|---|
| `locked` | 状态键不存在（`""`） | 前置未完成 | **不显示**（见 §2.4） |
| `NOT_ACCEPTED` | `notAccepted` | 前置已完成，等待与 NPC 对话接取 | 显示，可点「接受」 |
| `IN_PROGRESS` | `inProgress` | 已告知需求，世界目标进行中 | 显示，按钮改为「查看需求」 |
| `ready`（计算态） | 不落盘 | `IN_PROGRESS` 且世界目标已达成 | 显示 |
| `FINISHED` | `finished` | 已交付，下一阶段解锁 | 显示「已完成」 |

**推进规则（不可绕过）：**

- `accept`：只能在对话中由「首次需求页」触发；效果 `NOT_ACCEPTED → IN_PROGRESS`。
- `complete`：只能在对话中由「交付页」触发，且**必须校验世界目标**；效果 `IN_PROGRESS → FINISHED`，并同时：
  1. 发放奖励（`InventoryOperation.giveItemStackWithMSG`）；
  2. 把下一阶段置为 `NOT_ACCEPTED`；
  3. 推送消息 + 音效（`PLAYER_LEVELUP`）；
  4. 把 waypoint 换成下一阶段的目标点；
  5. 若下一阶段是同一个 NPC，**在同一次对话里直接重建为它的 `first` 页**（`DialogManager` 重建 page 即可）。
- 击杀 / 到达 / 升级 / 通关只更新**计数与进度**，绝不改任务状态。
- 纯对话阶段（`kind: talk`）没有世界目标：`first` 页选项直接是 `complete`。
- 主线任务的「提交」入口**只在对话里**；任务列表的提交按钮对主线不发送 `MissionSubmitC2SPacket`（改为提示「请与 XXX 对话」）。

### 1.3 为什么用对话做触发点

- 对话树是服务端权威状态机：`DialogManager` 已做「会话 + 距离 + 时间窗 + 动作白名单」校验，客户端无法伪造推进。
- 旧引导靠 `trigV2(tag)` 散落在击杀、等级、右键、锻造等事件里，条件与顺序耦合严重；改为对话后，**每个阶段的入口只有一处**。
- 剧情、需求、支线提示都可以挂在同一棵树上，后续补剧情不影响逻辑。

### 1.4 对话文本规范（本期）

1. 只写**需求告知**：去哪、打什么、多少、带回什么、找谁。
2. 剧情只放 `【剧情占位】` 行，不写正文；每页最多 2 行占位。
3. 一页 ≤ 8 行；超出的信息拆到下一页或放进任务详情。
4. 选项固定用「我明白了 / 开工 / 交付 / 告辞 / 稍后」这类短句。
5. 所有页都带说话人 `speaker`；颜色由实现侧统一（建议 `CustomStyle` 中已有序章 / 地区风格）。

### 1.5 世界与坐标系假设

- 本文落点坐标取自主世界现有路径点（`MyWayPoint.VillageWayPoint` / `MyWayPoint.overworldPointList` / `MissionV2Helper.exploreNameToPosMap`）。
- 若新流程运行在新维度 `vmd:survival_world`（见 `data/vmd/dimension/survival_world.json`），**所有坐标需按该维度重新标定**，本文坐标仅作结构参考。
- 维度统一写 `minecraft:overworld`；特殊维度在阶段内单独标注。

### 2.2 MissionV2 主线枚举模板

```java
MAIN_05_PLAIN_PURGE(Te.s("平原清剿", CustomStyle.styleOfPlain),
        Te.s("清剿平原僵尸"),                 // 任务列表第二行（描述）
        Te.s("平原村 · PP"),                   // 任务列表第三行（提示）
        Te.s("需完成 平原村的请求"),           // 前置条件显示
        false,                                 // canAutoSubmit = false（只能对话交付）
        MainQuestHelper.allow("main_05_plain_purge"),      // allowAcceptCondition
        null,
        MainQuestHelper.condition("main_05_plain_purge"),  // submitCondition（世界目标）
        MainQuestHelper.submit("main_05_plain_purge"),     // submitAction（奖励 + 解锁下一阶段）
        List.of(),                              // rewardDescription（悬停显示，动态更佳）
        null, null,
        MainQuestHelper.detail("main_05_plain_purge"),     // detailOperation（悬停显示当前进度）
        true)                                   // multiStep = true（阶段化）
```

> 主线任务的 `submitAction` 与对话的 `complete` 动作**共用** `MainQuestHelper.submit(stage)`，避免两套推进逻辑。
>
> 新增枚举后，必须同步 `MissionV2.getCategory()` 的 `switch`：`case MAIN_XX_YYY -> Category.MAIN;`。当前实现故意不写 `default`，新增任务时会编译报错，避免漏分类。

### 2.3 对话树数据（每个阶段）

对话树按「当前阶段状态」选择入口页，与 `EntrustmentTree` 的四态写法一致：

| 入口 | 条件 | 内容 |
|---|---|---|
| `first` | 本阶段 `NOT_ACCEPTED` | 需求告知；选项 `accept`（talk 阶段为 `complete`） |
| `progress` | 本阶段 `IN_PROGRESS` 且目标未达成 | 自动生成：「目标：<objective 文本>」；选项 `close` |
| `ready` | 本阶段 `IN_PROGRESS` 且目标达成 | 交付文案；选项 `complete` |
| `done` | 本阶段 `FINISHED` | 一句回访台词；选项 `close` |
| `idle` | 玩家当前阶段不是本 NPC 负责 | 一句指路台词；选项 `close` |

- 若玩家与 NPC 对话，但该 NPC 不是当前阶段的 `npc` / `report_npc`：进入 `idle`，台词取自 `MainQuestHelper` 的「当前目标向导」。
- `progress` 页文本由 `objective` 自动拼装，**不需要在本文逐阶段写**；需要特殊提示时在本阶段 YAML 加 `progress:` 一行覆盖。

### 2.4 任务列表可见性

- 主线任务未解锁时状态为 `""`，**不得**出现在任务列表（当前 `MissionScreen` 的「全部任务」会列出所有枚举，需要过滤）。
- 建议：`MissionV2` 增加 `boolean isUnlocked(Player)`（`Category.MAIN` 走 `MainQuestHelper`，其它分类恒 `true`），`MissionScreen.getFilteredMissions` 里统一过滤。
- 已完成阶段保留在「已完成」页，供回看。

### 2.6 落点与 waypoint

- NPC 落点按 §2.5 表写入 `vmd_npcs.json`（`dialogId` 必须显式填写，不能依赖显示名回退）。
- 阶段目标点用 `WaypointServerManager.addWaypoint` 下发，阶段完成时移除并下发下一阶段目标点；纯对话阶段指向 NPC 本体坐标。
- 阶段目标点坐标来源：`MyWayPoint.VillageWayPoint` 等，见 §3 表；NPC 坐标见 §2.5。

### 2.7 事件接入点

| 目标类型 | 接入点（现有代码） |
|---|---|
| `kill` | `LivingDeathEvent` 或现有 `Guide.incrementMobKill` 的调用处（建议迁移为 `MainQuestHelper.onMobKill`） |
| `level` | `Guide.handlePlayerTick` 的等级检测位置，改为写入进度，不触发阶段 |
| `reach` | 玩家 tick（每 20 tick 判一次距离） |
| `instance` | 各 `NoTeamInstance` / `NewTeamInstance` 的结算处回调 |
| `daily` | 东洋塔 `EasternTower`、炼魔塔 `ManaTowerData` 的每日奖励结算处 |
| `talk` | 无世界目标，对话即完成 |

### 2.8 支线触发

- 阶段 YAML 的 `unlock` 字段列出该阶段应向玩家开放的支线 id（§3 表已标注）。
- 实现方式建议：`MainQuestHelper` 记录已解锁支线集合，支线系统查询该集合决定是否可接；不要用「对话里直接发任务」的硬编码。
- 本期只做**提示**（对话里说出来）也可以，`unlock` 留作后续接线。

## 附录 A · 对话数据结构速查

```yaml
# 单个阶段的完整字段
stageId: main_xx_yyy          # 唯一 id（小写下划线）
mission: MAIN_XX_YYY          # MissionV2 枚举名
title: 任务名                  # 任务列表标题（建议 ≤ 8 字）
description: 描述              # 任务列表第二行（建议 ≤ 6 字，超出截断）
tips: 地点 · NPC              # 任务列表第三行
frontCondition: 需完成 xxx     # 前置条件显示
npc: dialog_id                # 告知 NPC
report_npc: dialog_id         # 交付 NPC（缺省 = npc）
kind: talk | objective        # 纯对话 / 有世界目标
open: 上一阶段 stageId         # 解锁条件
objective:                    # 世界目标（可多条，全部满足才算 ready）
  - {type: kill, mob: 怪物名, count: 10}
  - {type: reach, name: 地点, pos: [x, y, z], radius: 80}
  - {type: level, value: 15}
  - {type: hasItem, item: 物品, count: 1}
  - {type: instance, name: 副本, clear: 1}
  - {type: daily, name: 挑战, times: 1}
  - {type: talk, npc: dialog_id}
submit: dialogue              # 固定值：只能对话交付
unlock: [支线 id, ...]        # 本阶段开放的支线
reward:                       # 交付时发放
  - {item: 物品, count: 1}
waypoint: {name: 名称, pos: [x, y, z], dim: minecraft:overworld}
dialogue:
  first:                      # 首次（NOT_ACCEPTED）
    lines: ["..."]
    options: [{id: accept, label: "「我明白了」", hover: "...", next: close}]
  progress: "..."             # 可选：覆盖通用进行中文本
  ready:                      # 目标达成（IN_PROGRESS + ready）
    lines: ["..."]
    options: [{id: complete, label: "「交付」", hover: "...", next: null}]
  done: "..."                 # 完成后回访的一句
```

**actionId 语义：**

| id | 作用 |
|---|---|
| `accept` | `NOT_ACCEPTED → IN_PROGRESS`；仅 `first` 页可用 |
| `complete` | `IN_PROGRESS → FINISHED` + 发奖励 + 解锁下一阶段；仅 `ready` 页（talk 阶段为 `first` 页）可用 |
| `close` | 结束对话（`DialogManager.close`） |

**命名规范：**

- `stageId`：`main_{两位序号}_{短名}`，短名用拼音或英文，全小写。
- `mission`：`MAIN_{两位序号}_{SHORT_NAME}`，全大写。
- `dialogId`：小写下划线，不带 `vmd:` 前缀。
- 选项 `id`：小写英文。

## 8. 实机验收（1–29 阶段）

**准备**：重启服务器（`NpcRegistry.applyOnServerStart` 会按 `run/config/vmd_npcs.json` 生成 13 个主线 NPC），或在游戏内执行 `/vmd npc apply`。

**新玩家首次登录**：固定出生在 `MyRespawnRule.FIRST_RESPAWN_POS` (1801, 72, 252)，背包会获得一张身份卡，并自动弹出站台贝贝的第一段主线对话；点「我明白了」即接取 MAIN_01。已有 `FirstReward` 标记的玩家不会重复触发（测试新玩家流程需用新号或清掉该标记）。

**第一章流程**

1. 新玩家出生后直接点「我明白了」接取任务；老号可 `/tp @s 1799 72 253` 到旭升岛轻轨站，右键「秘书 - 贝贝」。
2. 按 HUD / 路径点前往天空城 (1005, 226, -3)；右键「秘书 - 贝贝」→ 选「交付」→ 自动进入 MAIN_02。
3. 选「收下物资」领取天空之锋 / 隼 / 杖 / 之心、食物与鞘翅。
4. 到 (956, 232, 19) 右键「天空城城主 - 索尔」→ 选「记住了」→ 第一章完成。

**后续章节**：按任务列表/HUD 提示找对应 NPC（平原 PP、雨林 Chen、海岸 Ushio、薰曦铁头、天空城辛Gi德/索尔/贝贝、北洋夫夫、风之高地索索、旭升岛托里、樱岛樱、绯樱村慎）接取与交付；击杀/通关/每日只涨进度，阶段仍由对话推进。

**验收检查**

- 阶段 2 后站台贝贝消失；阶段 3 前索尔不可见；后续 NPC 到各自阶段才出现；
- 任务列表「主线」只显示当前/已完成阶段，主线行没有「接受/提交」按钮；首次打开（或切换状态/分类）会自动跳到当前主线所在页；
- 左上角主线 HUD：阶段名 / **全部目标逐行列出** / 「按 L 打开任务列表」，高度随目标数量自适应；
- 战斗中 HUD 默认隐藏；若当前阶段有「击杀数量 &gt; 1」的目标，且玩家正在与该目标战斗（附近匹配目标或最近攻击/被攻击目标），HUD 保持显示；
- 击杀目标完成后显示绿色 **✓** + 删除线，击杀数不再增加；
- 完成「选择技能组」后玩家升 1 级并获得 1 点精通点；「精通配置」要求保存一次有点数变化的精通配置；
- 与 NPC 对话时按 **E**（或 Esc / 右上角 ×）可直接关闭对话，并同步清理服务端会话；
- NPC 对话中的地点名按对应地区颜色显示（天空城青、平原绿、雨林深绿、火山橙、樱岛粉、末地紫、圣光金等）；
- 委托迷你 HUD 显示在主线 HUD 下方（75 级后出现，Tab 开关附加界面）；
- `/vmd main info` 与 HUD 一致；重登后状态保持；
- 击杀数、副本通关、东洋塔/炼魔塔每日只涨进度、不直接跨阶段。

**GM 命令（仅管理员，权限等级 2）**：

- `/vmd main info [player]`：查看阶段、状态与目标；
- `/vmd main set <stageId> [player]`：跳到指定阶段（之前的阶段标记完成）；
- `/vmd main complete [player]`：强制完成当前阶段；
- `/vmd main reset [player]`：清空主线，从第一章重新开始；
- `/vmd main list`：列出全部阶段 id / 标题。

不写 `player` 时操作自己；控制台执行时用 `[player]` 指定在线玩家。可用 `set` 直接跳到任一章验收。
